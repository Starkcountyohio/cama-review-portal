## What This Project Is
A staff review portal for the Stark County Auditor's Office, Assessment Division.
Staff use it to compare MLS listing data against CAMA (iasWorld) property records
and review Grade/Condition mismatches weekly.

**Live URL:** https://starkcountyohio.github.io/cama-review-portal/
**Portal URL:** https://starkcountyohio.github.io/cama-review-portal/review_portal.html
**GitHub repo:** https://github.com/Starkcountyohio/cama-review-portal (public)

## Monday Weekly Workflow
**`ONBOARDING.md` is the authoritative runbook** — it covers the human gates, the
photo-review rules, the pre-push checks, and the known failure modes. Short version:
`run_weekly.py` (all-in-one) or `run_datapull.py` → Zillow photos → photo review →
`run_build.py` → commit + push → `create_future_year.py` → manual iasWorld steps.
Do not run `build_portal.py` by hand for a weekly deploy; the pipeline scripts call it
and also write `version.json` and the archive, which a bare build does not.

## Monthly Prompt Retraining Workflow
1. Run `python monthly_retrain.py --prompt-only` (add `--skip-recent 1` if retraining
   the same week as a build — that week's parcels have no appraiser decisions yet)
2. It reads the weekly archives in `archive/`, queries Oracle for the appraiser's
   current Grade/CDU, regenerates `Grade&Con_Compara.xlsx`, and rewrites the AI prompt
   inside `review_portal_template.html`
3. `--prompt-only` skips the rebuild/push — the new prompt ships with the next
   Monday build. Without it the script rebuilds and pushes immediately.
4. **Verify before it ships:** the template must still contain the
   `api.anthropic.com/v1/messages` block and must Babel-parse. The prompt rewrite has
   truncated the script before, blanking the portal to a navy screen.
5. **Check the Oracle layer-split line.** Appraisers record decisions on the
   FUTURE-year record (2027), not the current year — the script prefers that layer and
   falls back to the current one for older weeks. If a run reports everything from a
   single layer, or a near-zero change rate, it read the wrong layer.
6. `--weeks N` widens the window (default 4). Needed for a catch-up run: the script
   only ever takes the newest N archives, so skipped months are otherwise discarded.

## Tech Stack
- **Frontend:** React 18 + Babel + SheetJS — **SELF-HOSTED in `lib/`** (NOT from CDN: county network blocks unpkg.com & cdn.sheetjs.com → blank dark-navy screen). In-browser Babel transpiles JSX. Google Fonts still external (cosmetic only). `lib/` must stay committed.
- **Build:** Python 3, openpyxl, Pillow
- **Backend:** None — fully static site
- **Hosting:** GitHub Pages (public repo required for free Pages)
- **AI:** Anthropic Claude API (claude-sonnet-4-6), called direct from browser — model ID must be a current, non-retired model (claude-sonnet-4-20250514 was retired 2026-06-15)
- **API Key:** Set via ⚙️ button in portal bottom-right, stored in memory only — NEVER embed in HTML

## Key Domain Concepts
- **CAMA:** Computer-Assisted Mass Appraisal — iasWorld is the CAMA system
- **CDU:** Condition, Desirability, Utility — EX/VG/GD/AV/FR/PR (best to worst)
- **GRADE:** 2024 letter scale — X+/X/X- → A+/A/A- → B+/B/B- → C+/C/C- → D → E
- **EFFYR:** Effective Year Built — used for depreciation calculation
- **YRBLT:** Actual year built
- **SFLA:** Above-grade finished living area (sq ft)
- **FIXBATH/FIXHALF:** Full baths / half baths
- **SALEKEY:** iasWorld sale record identifier
- **NOPAR:** Number of parcels in the sale
- **WindowId:** iasWorld URL parameter needed to open parcel links
- **iasWorld URL pattern:** https://iasworld.starkcountyohio.gov/iasworld/Maintain/Transact.aspx?txtMaskedPin={parcelId}&windowId={windowId}

## AI Grade & Condition Prompt — Training History

### What the prompt is trained on:
The AI prompt inside `review_portal_template.html` is calibrated on ACTUAL
Stark County appraiser decisions — not just general appraisal theory.

### Training data used so far:
- **Current calibration: 1,074 parcels across W24–W34 (2026)**, retrained 2026-08-25
- `Grade&Con_Compara.xlsx` — Grade/CDU snapshot, regenerated by each retrain
- Prior calibrations: 355 parcels / W12–W16, and a W20–W23 refresh (2026-06-05)

### Key findings baked into the prompt (W24–W34, n=1,074):
- CDU changed on **28%** of parcels (156 upgrades / 147 downgrades), Grade on **13%**,
  either on **37%**
- Most common CDU changes: AV→GD (117x), GD→AV (91x), VG→GD (25x), AV→FR (18x),
  GD→VG (17x)
- Most common Grade changes: C→C+ (43x), B→B+ (13x), C+→C (12x), B-→C+ (11x)
- Downgrade signals: "fixer" 4.9x · "as-is" 3.2x · "sold as-is" 2.9x ·
  **"investor" 2.1x (13% of downgrades)** · "tlc" 2.0x
- Upgrade signals: "updated throughout" 4.6x · "new electric"/"new siding" 3.1x ·
  **"renovated" 2.7x (17% of upgrades)** · "new windows" 2.4x ·
  **"remodeled" 2.3x (24% of upgrades — still the biggest single upgrade word)** ·
  "turnkey" 2.2x
- Hard negatives (estate sale/cash only/vacant) → 39% change rate (n=23, thin)
- Location/school fluff → confirmed noise (35% of changed vs 38% of unchanged parcels)
- Median YRBLT of upgraded parcels: 1950
- Photo always outweighs remarks when they conflict

**Superseded by the 2026-08-25 retrain — do not cite these:**
- "CDU 35% / Grade 12%" — from the 355-parcel sample. The 35% is closer to today's
  *either-changed* 37%; CDU alone is 28%.
- **"opportunity" as the strongest downgrade word (43% of downgrades, 1.5x).** Still in
  the measured phrase list, but over 1,074 parcels it no longer clears the ranking
  threshold at all. Its multiplier was the weakest on that old list despite the largest
  share, so the original finding looks like a small-sample artifact.
- "as-is → 4x", "hard negatives → 88%", "hardwood → noise" — remeasured above, or no
  longer ranking.

> Rates below ~n=25 (hard negatives, "cash only", "new electric", "new siding") are
> thin enough to be anecdote. Treat the multiplier as a hint, not a calibration.

### Evidence weighting hierarchy (in prompt):
1. Photo (highest)
2. Hard negative language
3. Specific named system updates
4. Soft negative language
5. Positive generic language (lowest — realtor marketing)
6. Cosmetic only terms (ignore for CDU)

## Known Issues / Decisions Made
- GitHub Pages requires PUBLIC repo for free tier — key must NEVER be embedded in HTML
- API key is set manually via ⚙️ button each Monday session
- Chrome requires explicit window dimensions in window.open() to open new window vs tab
- iasWorld and Zillow open in named windows: "iasWorldWindow" and "zillowWindow"
- SharePoint cannot render HTML files directly — GitHub Pages is the solution
- localStorage cannot share state across remote users — no shared persistence currently
- Photos embed as base64 in HTML — 60-100 photos ≈ 20-40MB output file
